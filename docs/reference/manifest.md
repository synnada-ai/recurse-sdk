# `agent.yaml` manifest reference

Generated from the manifest specification the SDK validates with. Do not edit by hand.

The `agent.yaml` manifest declares a complete Recurse application: its identity, runtime, agent behavior, run input and output schemas, and tools. The shape is closed; unknown fields are rejected.

## `apiVersion`

*literal, required*

The manifest contract revision. Always `recurse.run/v1alpha1`.

Allowed value: `recurse.run/v1alpha1`

Example:

```yaml
apiVersion: recurse.run/v1alpha1
```

## `kind`

*literal, required*

The kind of application this manifest declares. Always `Agent`.

Allowed value: `Agent`

Example:

```yaml
kind: Agent
```

## `metadata`

*mapping, required*

Identity of the application shown to its callers.

### `metadata.name`

*string, required*

Stable application identifier. Also used as the deployed tool name.

Example:

```yaml
name: tiny-tuner
```

### `metadata.title`

*string, required*

Human-readable application title.

Example:

```yaml
title: Tiny Model Tuner
```

### `metadata.summary`

*string, required*

One-sentence description of what the application does. Also used as the deployed tool description.

Example:

```yaml
summary: Tunes a tiny classifier across feature and training configurations.
```

## `runtime`

*mapping, required*

The Python runtime the application executes in.

### `runtime.python`

*choice, required*

Supported Python release line.

Allowed values: `3.14`

Example:

```yaml
python: '3.14'
```

### `runtime.lockfile`

*literal, required*

The lockfile that pins the application's dependencies. Always `uv.lock`, generated by uv from the application's `pyproject.toml`; both files must be present and consistent.

Allowed value: `uv.lock`

Example:

```yaml
lockfile: uv.lock
```

## `agent`

*mapping, required*

The agent that drives the application's tools: its system prompt, optional model selection, and optional reliability limits.

### `agent.model`

*choice, optional*

Supported specialist model: `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol`, or `gpt-6-astra`. Omit to use the platform default (currently `gpt-5.6-luna`). The service also checks availability; models are never substituted. Preparation records the resolved selection, so existing deployments do not change when the default changes.

Allowed values: `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol`, `gpt-6-astra`

Example:

```yaml
model: gpt-6-astra
```

### `agent.prompt`

*path, required*

Relative path to the agent's system prompt file.

Example:

```yaml
prompt: prompt.md
```

### `agent.max_llm_errors`

*integer, optional*

Consecutive model errors tolerated before the run stops. `0` disables this limit.

Default: `3`

Example:

```yaml
max_llm_errors: 3
```

### `agent.max_tool_errors`

*integer, optional*

Consecutive tool batches in which every call fails, tolerated before the run stops; any successful call resets the count. `0` disables this limit.

Default: `5`

Example:

```yaml
max_tool_errors: 5
```

### `agent.timeout_tools`

*number or null, optional*

Timeout in seconds applied to each application tool call. `0` and `null` disable the timeout.

Default: `30`

Example:

```yaml
timeout_tools: 30
```

## `inputs`

*mapping, required*

JSON Schema (Draft 2020-12) describing run inputs. Supplied values are validated against it and property defaults are applied. The resolved `task` string, templated with `{{ input.NAME }}` placeholders, becomes the agent task; the remaining values are available to tools through `recurse.context().inputs`.

Example:

```yaml
inputs:
  type: object
  required:
  - target_f1
  properties:
    target_f1:
      type: number
    task:
      type: string
      default: Reach F1 {{ input.target_f1 }}.
  additionalProperties: false
```

## `outputs`

*mapping, required*

Self-contained JSON Schema (Draft 2020-12) describing the structured object returned by a successful run and exposed as the deployed MCP tool output schema.

Example:

```yaml
outputs:
  type: object
  required:
  - receipt
  properties:
    receipt:
      type: string
  additionalProperties: false
```

### `outputs.type`

*literal, required*

A successful run always returns one JSON object.

Allowed value: `object`

## `tools`

*mapping, required*

The application's tool module and tool registrations.

### `tools.source`

*path, required*

Relative path to the Python module that defines the tools. Every public module-level function must be registered.

Example:

```yaml
source: tools.py
```

### `tools.built_in`

*bool, optional*

Whether Recurse's built-in agent tools are also registered. Defaults to true.

Default: `True`

Example:

```yaml
built_in: true
```

### `tools.defaults`

*mapping, optional*

Default behavior settings applied to every registered tool. Per-tool settings override them.

#### `tools.defaults.no_storage`

*array, optional*

Parameter names for which the optional stored-object reference alternative is removed. This does not relax type requirements: in Recurse's strict mode, Any, including values inside dict[str, Any] or list[Any], still requires stored-object references. Use concrete types for inline data. Names must exist in the tool signature. Defaults to an empty list.

Default: `[]`

#### `tools.defaults.pure_args`

*array or null, optional*

Parameter names the tool guarantees not to mutate. Names must exist in the tool signature. Omit or use an empty list for conservative behavior; null declares all parameters pure.

Default: `[]`

#### `tools.defaults.volatile`

*bool, optional*

Whether repeated calls with the same arguments may return different results. Defaults to false.

Default: `False`

Example:

```yaml
volatile: true
```

#### `tools.defaults.storable`

*bool, optional*

Whether results may be stored and passed between tools by reference. When omitted, Recurse infers it from the tool's return type.

Example:

```yaml
storable: false
```

### `tools.register`

*mapping, required*

Tools to expose, keyed by public function name in `tools.source`. Each value is `~` (use defaults) or a mapping with the same keys as `tools.defaults`.

Example:

```yaml
register:
  extract_features: null
  train_model:
    volatile: true
```
